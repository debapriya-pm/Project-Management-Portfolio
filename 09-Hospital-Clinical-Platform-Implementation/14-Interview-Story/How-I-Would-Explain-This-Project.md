# Interview Narrative

## 60-Second Answer
“I created an end-to-end hospital implementation simulation to understand how an implementation PM manages a healthcare software rollout. I modeled myself as the Implementation Project Manager taking a fictional hospital from signed agreement through go-live and hypercare.

I translated an ambiguous objective into a charter, stakeholder map, requirements baseline and six-week plan. I mapped current and future workflows, coordinated a pharmacy workstream for institutional content validation, separated technical readiness from clinical validation, built UAT and go-live gates, created a training plan, managed a scope-change request, and built executive reporting.

The biggest lesson was that implementation is not just scheduling. The PM connects clinical, technical, operational and vendor stakeholders, identifies dependencies early, controls scope, and makes sure the organization is actually ready to go live.”

## If Asked What the PM Does
“I see the implementation PM as the person creating clarity and accountability across the implementation. I don’t make clinical or technical decisions outside my expertise. I make sure the right people are involved, requirements are clear, dependencies are tracked, decisions documented, testing completed, users trained, and risks escalated.”

## If Asked About Lack of Direct Implementation Leadership
“I haven’t independently owned a production hospital software implementation end-to-end yet. I have worked across healthcare operations, prior authorization, CRM support and cross-functional project coordination. To close that gap, I built this detailed implementation simulation. I deliberately worked through requirements, workflow mapping, RAID, configuration, UAT, training, change control, go-live readiness and hypercare. It gave me a concrete understanding of the lifecycle, dependencies and stakeholder responsibilities.”

**Important:** This is a simulation and should never be presented as a real client implementation.
